# AI use: loading fixes (freeze on loading, "The site did not load", faster loading screen)

| When | Who | Tool | What the AI did | What a person checked |
|---|---|---|---|---|
| 2026-11-15 | Yi Hung's session | Claude Code (Opus 5.5) | Found the cause of "THE SITE DID NOT LOAD" after "Start exploring": the site's code files carry a hash of their contents in their names, so a deploy renames them, and darksight.space (Cloudflare) answers a missing file with the page itself (`200 text/html`), which the browser refuses as a module. A page opened before a deploy then fails on the click; it happens only sometimes because the edge cache still holds old files for a while. Reproduced it with a local server that answers missing files the same way and swaps in a second build mid-visit. Fixes: (1) `vite.config.ts` lists the site's code (site, Plotly, three.js chunk, site CSS) in a `<meta name="site-code">`, and `main.ts` fetches those files without running them once the Sun and Earth table and the site list are in (`modulepreload`; the CSS as a stylesheet with media "not all", switched on at the click), so the click needs no download and a later deploy can't break it. (2) If the site's code still fails, the page reloads itself once (a mark in `sessionStorage`, at most once a minute, `ui/intro/model.ts`) and opens straight on the loading screen. (3) Plotly's basic build (`plotly.js-basic-dist-min`: scatter, bar, pie, every chart the site draws) instead of the full one: 385 KB sent instead of 1.4 MB, and about a quarter of the start-up time. Types come from the full build, now a dev dependency only (`src/plotly-basic.d.ts`). (4) `ui/plotly.ts` gives each chart's first draw a task of its own, so the charts no longer draw one after another in one long freeze. Measured `main` (`2bef3d6`) against the branch with Playwright in headless Chromium, built and served locally, Fast 4G and Slow 4G emulated over the DevTools protocol, also with the processor slowed 4x. Worst freeze after the click: 1.44 s to 0.12 s on Fast 4G, 5.4 to 6.2 s to 0.52 to 0.56 s with the processor slowed 4x. Charts drawn: 5.6 s to 2.3 s on Fast 4G, 10.3 s to 4.7 s on Slow 4G. Site shown after the click: unchanged when clicked at once, 0.2 to 0.4 s sooner when clicked after 6 s. The three charts, screenshotted on both builds at 1280 and 390 px wide: 0 pixels differ. Checks: `npm test` 597 of 597, `npm run build`, `npm run test:page` 12 of 12, `browser-check.py` 20 PASS and with `--public` 21 PASS | Yi Hung: reported the freeze on loading and "doesn't load" after "Start exploring" on darksight.space, and asked for a faster loading screen.

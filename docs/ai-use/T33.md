## Choices the AI made that the task doesn't spell out

- **The wait doubles after each failure in a row, up to 60 s.** The task asks for "a short wait (for example 10 s)". A fixed 10 s would ask for a dead file six times a minute for as long as the page is open; doubling keeps the first retry quick and the rest rare. The `online` event resets it.
- **A timer, not only the next action.** "Unblock and wait: the numbers come back without a reload" needs a retry when nobody touches the page, so a timer calls `notify()` when the next wait is over. One timer for all failed decades; a decade no longer needed is not asked for, and the timer does not keep firing for it.
- **Scope beyond the task's list:** `scene/index.ts` printed the same "outside" message for a failed decade; `ui/timeline/model.ts` and `ui/sky/index.ts` did too, so both changed (the task said to change them if needed); the new `ui/tableGap.ts` and its test; `e2e/decade-retry.spec.ts`.
- **The mission and launch simulation pages** (T34, their own pages since #145) said the landing time was "too near the edge of the table" for a failed decade. Yi Hung asked for that to be fixed here too: `missionFor` has a `'failed'` status with the decade's start, both pages use `noRowText`, and the mission page's status line lists the failed decades. The compare note ("the Sun and Earth table has fewer than 30 days after that time") is true in both cases and stays.
